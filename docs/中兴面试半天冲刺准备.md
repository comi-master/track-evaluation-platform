## 2. 项目介绍：2 分钟版本

### 2.1 多源航迹数据分析与报告管理平台

这是一个面向雷达、红外和融合航迹仿真数据的分析平台，解决原始 CSV 文件难以管理、解析和复用的问题。整体可以概括为四条链路：

1. 用户与权限：登录后通过 JWT 或 Web Session 识别用户；数据查询始终附带用户归属条件，普通用户只能访问自己的数据，管理员可以按权限扩大范围。
2. 文件与数据：上传的原始 CSV 作为对象保存到 MinIO；MySQL 保存数据集、文件元数据、解析状态和结构化航迹点。文件和数据库职责分离，便于大文件存储、下载和结构化查询。
3. 解析与分析：CSV 使用流式读取，按批次写入 MySQL，避免整文件加载造成内存压力。分析计算三维位置误差，输出 RMSE、最大误差、总体标准差和连续异常区间。
4. 异步任务与结果：创建分析任务后先记录任务状态，再把任务 ID 投递到 RabbitMQ；消费者取出任务并执行分析，成功后写入不可变分析结果并更新任务状态，前端通过查询接口或页面查看结果。Redis 缓存最新结果和多源对比结果，结果更新或任务完成时主动失效。

### 2.2 面试官问“数据怎么流转”时这样说

浏览器/客户端发起上传请求 -> Controller 接收 HTTP 参数和文件 -> Application Service 校验用户、文件格式和业务状态 -> Storage/MinIO 保存原始对象 -> Mapper 向 MySQL 写入数据集、文件元数据和解析状态 -> Track Parser 流式读对象 -> TrackPoint Mapper 批量写入航迹点 -> 创建分析任务并投递 RabbitMQ -> Consumer 领取任务 -> Analysis Service 读取航迹点并计算误差 -> Mapper 保存 analysis_result 和 abnormal_interval -> Redis 删除相关旧缓存 -> Controller 或 Web Controller 查询结果 -> 返回 JSON 或渲染 HTML。

关键点是：Controller 不负责业务规则；Service 编排一次完整用例；Mapper 只负责数据库读写；MinIO 存原始文件，MySQL 存可检索的结构化信息；RabbitMQ 负责把耗时分析从用户请求中剥离。

## 4. 你的项目高频追问与短答

### 为什么用 Spring Boot？

Spring Boot 是基于 Spring 的快速应用框架，通过自动配置、Starter 依赖和内嵌 Tomcat，把 Web、数据库、校验、安全等基础设施快速组装起来。项目启动后 Tomcat 监听端口，Spring MVC 把请求路由到 Controller，Service 执行业务，Mapper 访问 MySQL。它解决的是应用基础设施装配问题，不等于业务代码本身。

### Controller、Service、Mapper 分别做什么？

Controller 只做 HTTP 适配：接收参数、调用用例、返回 JSON/页面。Application Service 表示一个业务用例，负责校验、编排多个组件、控制事务边界。Mapper 是 MyBatis 对数据库的访问接口，负责 SQL 映射和结果转换。这样分层的价值是职责清楚，业务规则不会散落在 HTTP 层或 SQL 层。

### MinIO 与 MySQL 的区别？

MinIO 是对象存储，保存 CSV 的原始字节，类似一个私有的文件服务器，按 bucket/object name 管理。MySQL 是关系数据库，保存 dataset、track_file、track_point、analysis_result 等结构化记录。MySQL 中可以保存 CSV 的文件名、大小、SHA-256、对象名、解析状态和归属用户，但不适合把整个大文件作为普通业务字段反复查询。两者通过 dataset_id、track_file_id 和 object_name 关联。

### RabbitMQ 与高并发有什么关系？

RabbitMQ 本身不是“让所有代码自动变快”，它提供生产者、队列、消费者之间的缓冲和解耦。用户创建分析任务时只需快速记录任务并投递 task ID，HTTP 请求不用同步等待完整分析。消费者可以按机器资源扩展并发数量，队列可以吸收突发流量，失败消息可以重试或进入死信队列。代价是系统变成最终一致，需要任务状态、重复投递、幂等和失败恢复设计。

### Redis 做什么？是否必须用于登录？

Redis 是独立的内存型键值数据库工具。项目中可以用于 Web Session、缓存最新分析结果、缓存多源对比结果和短期状态。JWT API 鉴权本身不一定需要 Redis，因为服务端可以验证签名和过期时间；Web Session 通常需要 Redis 保存会话，使多个应用实例共享登录状态。但 Redis 不是数据库的替代品，缓存丢失后应能从 MySQL 或任务状态恢复。

### JWT 是什么？

JWT 是服务端签发给客户端的一段带签名的身份凭证。登录时服务端校验用户名密码，成功后生成 JWT；客户端以后把 JWT 放在 Authorization: Bearer 头中发送给服务端；服务端验证签名、过期时间和用户状态后，才允许访问接口。它不是“双向传输器”，而是服务端签发、客户端携带、服务端验证的单向凭证流。JWT 通常可被解码读取，因此不要放密码等敏感信息；签名保证内容未被篡改，但不等于加密。

### 登录为什么是后端校验密码？

网页只负责收集用户名和密码并通过 HTTPS 提交。真正的密码校验必须在后端，因为用户数据、密码哈希和权限规则不能交给浏览器决定。后端从 MySQL 查询用户的密码哈希，用安全的密码算法比对；成功后生成 Session 或 JWT，浏览器只保存凭证，不保存明文密码。

## 5. Java 基础高频题

### ==、equals、hashCode

基本类型的 == 比较值；对象的 == 比较引用是否指向同一个对象。equals 用于逻辑相等判断。重写 equals 就必须按同样字段重写 hashCode，否则 HashMap/HashSet 会出现查找和去重异常。可背：相等对象必须有相同 hashCode，hashCode 相同不代表一定相等。

### ArrayList、LinkedList、HashMap

ArrayList 基于连续数组，随机访问快，尾部追加通常快，但中间插入要搬移元素。LinkedList 节点分散，按下标访问慢，只有已经定位节点时插入才有优势，工程中不应因为“插入快”就默认使用它。HashMap 用哈希定位桶，平均查找接近 O(1)，需要正确的 equals/hashCode；高冲突桶在新版本 Java 中会树化以改善最坏情况。

### HashMap 为什么线程不安全？ConcurrentHashMap 怎么做？

HashMap 没有为并发读写提供一致性保证，扩容和结构修改可能造成数据丢失或异常。ConcurrentHashMap 通过更细粒度的并发控制和 CAS 等机制降低锁竞争，并禁止 null key/value 来避免并发语义歧义。多线程共享数据时不能只看“读多写少”，还要明确可见性、原子性和复合操作是否安全。

### synchronized、volatile、Lock

synchronized 同时提供互斥和可见性，并且会自动释放锁；volatile 只保证变量读写的可见性和一定的有序性，不能保证 count++ 这种复合操作原子；Lock 提供可中断、超时、公平策略等更灵活能力，但必须在 finally 中释放。选择依据是临界区、竞争程度和是否需要高级锁能力。

### 线程池参数怎么考虑？

核心线程数、最大线程数、队列、线程工厂和拒绝策略要结合任务类型。CPU 密集型通常接近 CPU 核数，I/O 密集型可以更多但要受下游容量约束；无界队列可能掩盖过载并造成内存增长。项目中的分析任务更适合由 RabbitMQ 控制任务堆积，消费者并发要与 CPU、MySQL 连接池和单任务内存共同评估。

### JVM 内存和 GC

线程私有的程序计数器、虚拟机栈和本地方法栈记录执行状态；堆存放对象，是 GC 主要区域；方法区/元空间存放类元数据。GC 回收不可达对象，常见思路是分代回收。排查内存问题要区分堆对象增长、线程栈过多、直接内存、文件句柄和外部资源泄漏，不能只盯着堆。

### 异常、接口、抽象类

异常用于表达不能在当前层正常完成的情况；不要空 catch，也不要用异常代替正常分支。接口表达能力契约，抽象类可以复用状态和部分实现。项目中应用服务依赖基础设施接口，有利于单元测试和替换实现，但不为只有一个实现且没有边界价值的类强行抽象。

### Spring IOC、AOP、事务

IOC 是对象由 Spring 容器创建和注入，降低组件之间的直接耦合。AOP 把日志、事务、权限等横切关注点织入方法调用，减少重复代码，但不能替代业务编排。事务应放在应用服务的用例边界，保证 MySQL 内多个写操作的一致性；MinIO、RabbitMQ 与 MySQL 不共享同一个本地事务，外部调用必须考虑失败补偿、重试和状态恢复。

## 6. 操作系统、Linux 与底层方向

### 进程和线程

进程是资源隔离和分配的基本单位，线程是 CPU 调度的基本执行单位，同一进程线程共享地址空间和大部分资源。多线程减少创建和通信成本，但引入竞态、死锁和上下文切换。系统服务需要明确哪些状态共享、谁负责同步、线程退出如何回收。

### 虚拟内存、页表、缺页

每个进程看到的是虚拟地址空间，CPU 通过页表把虚拟地址映射到物理页。访问尚未装入内存的页面会触发缺页异常，由内核装入或建立映射。频繁缺页会导致抖动；大文件处理应采用流式读取、合理缓冲和批量 I/O，项目的 CSV 流式解析正对应这个工程思想。

### 中断、系统调用和驱动

外设事件通过中断通知 CPU，内核中断处理程序先做快速、必要的处理，再把耗时工作推迟到下半部或工作队列。用户程序通过系统调用进入内核，例如文件读写。驱动通常负责把硬件寄存器/总线操作封装成内核可管理的设备接口。面试被问 I2C/SPI 时要说明：I2C 有地址、两线、可多设备、速度相对低；SPI 通常四线、片选明确、吞吐高但设备需要片选。

### 死锁四条件

互斥、占有且等待、不可剥夺、循环等待。预防方法包括统一锁顺序、减少锁范围、超时尝试获取、避免在持锁时调用未知外部代码。排查要看线程 dump、锁等待链和业务调用栈。

### Linux 排查性能问题

先确认现象和指标，再定位 CPU、内存、I/O、锁、网络或下游数据库。常用 ps/top 看进程资源，vmstat 看系统状态，iostat 看磁盘，ss 看连接，jstack 看 Java 线程栈，jmap/JFR/GC 日志看 JVM。若方向需要，可继续学习 perf、simpleperf、systrace；回答时强调“先测量再优化，优化后复测”。

### Bootloader、Kernel、HAL 的关系

Bootloader 在操作系统启动前完成硬件初始化、加载内核和传递启动参数；Kernel 管理进程、内存、设备、文件系统和网络；HAL 用相对稳定的接口把上层系统服务与具体硬件实现隔离。Android 中常见链路是应用 -> Framework/System Service -> HAL -> Kernel Driver -> Hardware。你可以说自己当前主要做应用/平台层和算法系统，正在补齐这条链路。

## 7. 性能与系统设计题的统一答法

遇到“如何优化一个系统”，按五步回答：

1. 先定义指标：延迟、吞吐、CPU、内存、功耗、错误率、P99，而不是只说“更快”。
2. 建立基线：固定输入、场景和并发，记录端到端和分阶段耗时。
3. 找瓶颈：CPU 计算、锁竞争、内存分配、磁盘/网络 I/O、数据库索引、队列堆积或下游容量。
4. 选择措施：批量 I/O、流式处理、缓存、异步队列、并发控制、数据结构优化、减少拷贝，必要时才换算法或硬件加速。
5. 验证回归：比较同一指标，检查正确性、资源上限和异常场景，避免用局部平均值掩盖 P99 和稳定性问题。

项目落点：CSV 解析用流式和批量写入降低内存和数据库往返；分析任务用 RabbitMQ 剥离请求线程；Redis 降低重复查询；但仍要监控队列长度、消费者耗时、MySQL 连接池和缓存命中率。

### 你项目中最难的问题是什么？

可以答“异步任务的一致性和可恢复性”。任务不能只投消息不落库，也不能把耗时分析放在 HTTP 请求里。需要先有任务记录和状态，再投递 task ID；消费者要有状态校验、幂等、失败重试和最终状态更新；结果只在成功后关联。这样即使消息重复或进程重启，也能根据数据库状态恢复，而不是生成多个错误结果。

### 你怎么证明优化有效？

先建立相同数据集和相同并发下的基线，分别统计上传/解析、批量写入、分析计算、结果查询的耗时、内存和数据库 QPS。优化后用同样场景复测，并关注 P95/P99、错误率和资源峰值。只说“用了 Redis 所以快”是不完整的。

### 如果 Redis 挂了怎么办？

缓存故障不应让核心数据永久丢失。查询可以降级到 MySQL，写入仍以 MySQL 为准；缓存重建要防止击穿，可使用过期、互斥重建或限流。Session 场景要根据业务决定是否要求重新登录或使用高可用 Redis。缓存异常应有日志和指标，但不打印密码、Token 或完整 key。

### 如果 RabbitMQ 挂了怎么办？

任务创建要有明确状态，投递失败不能假装成功；可以让任务保持待发布并由重试机制补发，或者采用可靠消息/Outbox 思路。消费者处理成功后再确认消息，失败进入重试或死信。数据库和消息队列不是一个事务，所以必须设计可恢复状态。

## 9. 算法与研究方向可能追问

### RMSE 怎么算？

对每个点的三维位置误差先得到 e_i = sqrt((dx_i)^2+(dy_i)^2+(dz_i)^2)，RMSE = sqrt(sum(e_i^2)/N)。要先明确是对三维坐标分量做均方根，还是对欧氏距离序列做统计，避免口径不清。最大误差记录峰值及对应时间；标准差要说明总体还是样本口径。

### 异常区间怎么识别？

先用阈值把每个点标记为正常/异常，再按序号或时间连续扫描，把相邻异常点聚合成区间，输出起止位置、点数、峰值和时间。边界要考虑单点异常、文件末尾异常、时间不连续和空数据。工程上还要固定阈值来源、单位、NaN/Infinity 处理和测试样例。

### 多源融合最重要的工程问题是什么？

时间对齐、坐标系统一、量测质量评估、异常观测剔除、数据关联和不确定性传播。算法效果不只由公式决定，还取决于输入时间戳、传感器噪声、丢包、杂波和异常值处理。

## 10. 面试官可能让你手写/口述的 Java 题

1. 两数之和：HashMap 记录已见值和下标，平均 O(n)，说明空间 O(n)。
2. LRU：HashMap + 双向链表，查找 O(1)，移动和淘汰 O(1)。
3. 生产者消费者：有界队列 + 条件等待，说明满/空时如何阻塞、如何退出。
4. Top K：小顶堆 O(n log k)，或快速选择平均 O(n)。
5. 二叉树遍历：递归和显式栈，说明深度过大时递归栈风险。
6. 合并区间：按左端点排序，扫描维护当前区间，O(n log n)。

写代码时先说输入约束、空值、重复值、溢出和复杂度，再写主逻辑；不要一上来默写代码。
