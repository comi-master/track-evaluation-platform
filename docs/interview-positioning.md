# 项目包装与面试表达

## 推荐定位

将项目包装为：

**个人实验室项目：航迹仿真数据生成与跟踪算法评测平台。**

它本质上是个人项目，但“个人实验室项目”比“简单的个人 CRUD 项目”更准确：平台服务于算法实验，具有可复现数据、统一 CSV 协议、自动指标计算、结果可视化、多用户隔离和异步任务支撑。

不要声称这是某个真实研究所、铁路公司或银行的生产系统；应明确说明数据是可控仿真数据，系统在本地 Docker 环境完成验证。

## 解决的问题

航迹算法实验通常需要反复生成相同条件的数据、运行不同算法、计算误差并比较结果。若每个人使用独立脚本，数据参数、随机种子、指标实现和结果保存方式不一致，实验难以复现和公平比较。

本项目把这些步骤收敛为一个平台：生成可复现仿真数据，接收算法输出，按统一协议计算指标，并保存和绘制结果。

## 一分钟介绍

我做的是一个面向航迹跟踪算法实验的仿真数据生成与评测平台。它允许用户配置运动模型、二维或三维空间、目标数量、噪声和随机种子，生成包含真实轨迹与观测轨迹的 CSV。用户用自己的算法处理后，再上传算法输出，平台统一计算 RMSE、MAE、异常点、速度误差、末点误差和连续性，并把真实轨迹、仿真观测和算法轨迹画在同一张图上。

在工程实现上，我使用 Spring Boot 提供 REST 和网页两类入口，MySQL 保存用户、场景、轨迹点和评测结果，MinIO 保存文件，RabbitMQ 支撑异步分析，Redis 保存网页 Session。系统通过用户 ID 和所有权校验隔离多用户数据，并通过唯一约束、任务状态、租约和失败恢复处理并发与异常情况。当前版本在 Docker 局域网环境完成了自动化测试和运行验证。

## 面试重点

- 为什么要统一随机种子：保证实验可复现。
- 为什么真实轨迹和观测轨迹同时保存：真实轨迹作为评价基准，观测轨迹模拟传感器输入。
- 为什么文件和点要入库：支持分页、指标计算、历史查询和数据归属校验。
- 为什么要异步任务：大批量解析和分析不能阻塞 HTTP 请求。
- 如何处理用户隔离：用户名用于登录，数据库用户 ID 用于所有权关联，服务层再次校验归属。
- 如何处理 Worker 故障：任务租约过期后允许恢复，状态机和幂等约束避免重复完成。
- 如何证明高并发：通过多用户同时上传、提交和查询，记录吞吐量、P95、失败率和队列长度；不虚构未测得的数字。

## 诚实的边界

这是一个可运行的个人实验室平台，不应包装成已服务真实陌生用户的商业系统。它的价值在于把算法实验流程工程化，并展示后端开发、数据处理、异步可靠性、安全隔离和可视化能力。
